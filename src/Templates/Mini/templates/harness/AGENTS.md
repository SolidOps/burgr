# AGENTS.md

The API code of this repository is generated by [Burgr](https://github.com/SolidOps/burgr)
from a YAML model, with the **Mini** template set (ASP.NET Core Minimal API + EF Core).
You write the model and the extension points, Burgr writes the rest, the tests decide.

## Workflow

1. Change the model: the `*.yaml` files next to `burgr.json`.
2. Regenerate: `dotnet burgr <directory of burgr.json>`.
3. Build: the compiler lists the extension points the model now requires (a calculated
   property needs its `Calculate…()` method).
4. Write the hand-written code and its tests, then `dotnet build` and `dotnet test`.

## Generated files

A generated file is named `<GeneratedFilePrefix><name><GeneratedFileSuffix>.<ext>`, two
settings of `burgr.json` (empty prefix and `.g` suffix by default: `*.g.cs`).

**Allowed:**

- edit the YAML model, then regenerate;
- write the extension points below, the tests, `Program.cs` and any other hand-written file;
- search a generated file with Grep to find a signature or a type name.

**Forbidden:**

- edit, create or delete a generated file by hand: the next generation overwrites it;
- read a generated file in full (Read, `cat`, `Get-Content`…): this file documents what it
  contains, and a targeted Grep answers the rest for a fraction of the tokens;
- write by hand what the generator produces (CRUD endpoint, DTO, EF configuration), or copy
  generated code into a hand-written file.

The hook `.claude/hooks/block-generated-files.sh` refuses Read, Edit and Write on generated
files. A refusal is the signal to use Grep, the model or an extension point, not an
obstacle to work around with shell commands.

## The model

```yaml
burgr-model-version: 1.0.0

aggregate_roots:
  author:
    properties:
      name:
        is_unique: true
        field_size: 100
      biography: string?
      books: ->book[]        # navigation: book must reference author
    api:
      query:
      get:
      add:
      update:
      remove:

  book:
    properties:
      title:
        field_size: 200
      copies: int
      status: $book_status   # enum
      author: author         # reference: AuthorId + Author
      is_available: =bool    # calculated, implemented by hand

enums:
  book_status:
    values:
      Draft: 0
      Published: 1
```

- Names are snake_case in the model, PascalCase in C# (`is_available` → `IsAvailable`).
- Scalar types: `string`, `int`, `long`, `decimal`, `double`, `bool`, `datetime`, `guid`;
  `?` makes a property nullable. A property without a type is a `string`.
- Property options: `field_size` (default 255 for strings), `is_unique`, `is_private`
  (kept out of the DTOs), `is_readonly` (kept out of the inputs).
- `api:` lists the endpoints to generate: `query`, `get`, `add`, `update`, `remove`.
- Burgr refuses a model using anything this set does not support (entities, value
  objects, transients, services, events, rights, composite keys, collections of scalars…)
  and names the feature.

## What is generated

For each aggregate root `X`, in the namespace `<NamespaceName>.<ProjectName>`:

| Type | Contract |
|---|---|
| `Domain.X` | `partial class`: `Id`, properties, `YId` and `Y` for a reference, `List<Y>` for a navigation, one enum per model enum. |
| `Contracts.XDto` | Read model returned by the API, `static XDto From(X)`. Navigations are filled by `GET /{id}` only. |
| `Contracts.XInput` | Body of `POST` and `PUT`: `Validate()` (required strings, maximum lengths, enum values), `ApplyTo(X)`. |
| `Infrastructure.<ProjectName>DbContext` | `DbSet<X> Xs`, keys, maximum lengths, unique indexes, enums stored as strings, calculated properties ignored. Relationships follow EF Core conventions. |
| `<ProjectName>.csproj` | Written only when missing: Web SDK, `net10.0`, `Microsoft.EntityFrameworkCore`. Add the package of your database provider. Never overwritten afterwards. |
| `Api.<ProjectName>Endpoints` | `Map<ProjectName>Endpoints()`: a `/xs` group with `GET /`, `GET /{id}`, `POST /` (201), `PUT /{id}`, `DELETE /{id}` (204), as listed in `api:`. 400 with a validation problem (unknown reference included), 404, 409 when a unique index or a foreign key is violated. |

## Extension points

| Where | What |
|---|---|
| `Program.cs` | Database provider, schema creation (`EnsureCreated` or EF migrations), JSON options, authentication, `app.Map<ProjectName>Endpoints()`, any other endpoint. |
| `partial class X` (namespace `Domain`) | `private partial T CalculateP()` for each calculated property `P` (required: the build fails without it), domain methods. |
| `partial class XInput` (namespace `Contracts`) | `partial void OnValidating(Dictionary<string, string[]> errors)`: validation rules of your own, run after the generated ones. |
| `partial class <ProjectName>DbContext` (namespace `Infrastructure`) | `partial void OnModelCreatingPartial(ModelBuilder modelBuilder)`: indexes, seeding, relationship overrides. |

## Testing

Integration tests through the real endpoints, with `WebApplicationFactory<Program>`
(`Microsoft.AspNetCore.Mvc.Testing`) and a throw-away SQLite database. Test what was written
by hand: each calculated property, each `OnValidating` rule, each custom endpoint, plus one
round trip per aggregate root to catch a model change that breaks the API.
