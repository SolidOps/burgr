# AGENTS.md

The API code of this repository is generated by [Burgr](https://github.com/SolidOps/burgr)
from a YAML model, with the **Onion** template set: an ASP.NET Core API in onion
architecture, with EF Core and a light framework of its own.
You write the model and the extension points, Burgr writes the rest, the tests decide.

## Workflow

1. Change the model: the `*.yaml` files next to `burgr.json`.
2. Regenerate: `dotnet burgr <directory of burgr.json>`.
3. Build: the compiler lists the extension points the model now requires (a rule, a
   service method, a factory, a calculated property).
4. Write the hand-written code and its tests, then `dotnet build` and `dotnet test`.

## Three kinds of files

| Name | What | Rewritten by Burgr | Read | Edit |
|---|---|---|---|---|
| `*.g.cs`, `*.g.puml` | generated from the model | at each generation | no: Grep only | never |
| `*.f.cs` (folders `Framework/`) | the framework of the set, the same for every model | at each generation | yes, to understand a behavior | never |
| any other file | `Program.cs`, partial classes, tests, project files | never | yes | yes |

The suffixes are `GeneratedFileSuffix` (`.g`) and `FrameworkFileSuffix` (`.f`) of
`burgr.json`, after `GeneratedFilePrefix` (empty).

**Allowed:** edit the model then regenerate; write the extension points below, the tests,
`Program.cs`, any hand-written file, the project files (written once by Burgr, yours
afterwards); read a framework file; search a generated file with Grep for a signature.

**Forbidden:** edit, create or delete a generated or framework file by hand (the next
generation overwrites it); read a generated file in full (Read, `cat`, `Get-Content`…):
this file and a targeted Grep answer for a fraction of the tokens; write by hand what the
generator produces (CRUD endpoint, DTO, EF configuration, repository), or copy generated
code into a hand-written file.

The hook `.claude/hooks/block-generated-files.sh` refuses Read, Edit and Write on
generated files, and Edit and Write on framework files. A refusal is the signal to use
Grep, the model or an extension point, not an obstacle to work around with shell commands.

## Projects

For a module `M` (the `ProjectName` of `burgr.json`), in the namespace
`<NamespaceName>.M.<Layer>`:

| Project | Generated | Framework | References |
|---|---|---|---|
| `M.Domain` | aggregate roots, entities, value objects (records), enums, `IXRepository` | `Entity`, `AggregateRoot`, `IRepository<T>`, `PageRequest`, `Page<T>` | nothing |
| `M.Application` | DTOs, inputs, transients, CRUD services, model services and factories, events, `MRights`, `AddMApplication()` | `Result<T>`, `Error`, `IUnitOfWork`, `Paging`, `ICurrentUser`, `IValidatable`, events | Domain |
| `M.Infrastructure` | `MDbContext`, repositories, `AddMInfrastructure(configureDatabase)` | `EfRepository<T>`, `UnitOfWork`, `ModelConventions` | Application |
| `M.Api` | endpoints, `MapMEndpoints()` | `HttpResults`, `Security` (`AddMApi()`), `Program` made public | Application, Infrastructure |
| `M.Tests` | per aggregate root: the query answers, refuses an anonymous caller, an unknown id gives 404 | `ApiTestBase` | Api |
| `M.Diagrams` | `MClasses.g.puml`, the class diagram of the model | | |

## The model

```yaml
burgr-model-version: 1.0.0

aggregate_roots:
  user:
    properties:
      email:
        is_unique: true
        field_size: 50
      preferences: preferences?   # value object, stored as JSON
      user_rights: ~>user_right[] # synchronized children, edited with the user
      is_admin: =bool             # calculated, implemented by hand
    dependencies:
      local_user: read            # repositories given to the rules and factories
    rules:
      before_add:
        - create_local_user       # partial method of UserService, written by hand
    factories:
      create_local:
        inputs:
          email:
    event_produced: add|remove    # UserEvent published after the change is saved
    api:
      query:
      get:
      add:
        mandatory_right: ManageUsers
      update:
        mandatory_right: ManageUsers
      remove:
        mandatory_right: ManageUsers

entities:
  user_right:
    properties:
      user:
        type: user
        multiple_unique_constraint_with: right
      right: right

value_objects:
  preferences:
    properties:
      language:
        field_size: 10

services:
  authentication:
    api_description:
      is_anonymous: true
    methods:
      login:
        result: string
        inputs:
          request: login_request
        api_description:
          force_post: true        # an object input of a method returning a value
    dependencies:
      local_user:

transients:
  login_request:
    properties:
      login:
      password:

events:
  invite_used:
    data_type: invite_result      # a transient or an aggregate root
```

- Names are snake_case in the model, PascalCase in C#.
- Scalar types: `string`, `int`, `long`, `decimal`, `double`, `bool`, `datetime`, `guid`;
  `?` makes a property nullable; `$name` is an enum; a property without a type is a `string`.
- References: `name: other` (a foreign key `OtherId` and a navigation); `->x[]` a
  navigation to the objects referencing this one; `~>x[]` the same, synchronized.
- Burgr refuses a model using anything this set does not support (composite keys,
  references to another module, collections of scalars, calculated collections, UI
  components) and names the feature. `event_consumers`, `after_mapping` and
  `ownership_override_right` are ignored.

## Behavior

- **Aggregate root:** its own table and repository; `api:` gives the endpoints
  `GET /xs?page&pageSize&orderBy&descending`, `GET /xs/{id}` (with its list navigations),
  `POST /xs` (201), `PUT /xs/{id}`, `DELETE /xs/{id}` (204). 400 with the validation errors
  by property path, 404, 409 when a unique index or a foreign key is violated.
- **Entity:** its own table, reached through the navigation of its aggregate; no
  repository and no endpoint. Deleted with the aggregate root it references; any other
  reference prevents the deletion of what it references (409).
- **Value object:** a record stored as JSON in the row of its owner, validated with a path
  (`Preferences.Language`).
- **Synchronized navigation:** the input of the parent holds the whole list of children; a
  child without `Id` is added, a child missing from the list is removed. A reference of a
  child to an aggregate root is not in its input: the navigation sets it.
- **Service:** `IXService` and the partial class `XService`; each method exposed (`api`,
  `api_description`) is an endpoint `/x/method`. A transient input is validated before the
  method runs (400).
- **Transient:** a self-validating DTO `XDto` of the application layer.
- **Rights:** an endpoint requires an authenticated user, unless `is_anonymous: true`; a
  `mandatory_right` requires the claim `right` with that name, or `*` which grants every
  right. Authentication is configured in `Program.cs`.
- **Rule:** a partial method of the CRUD service, run before or after an add, update or
  remove; it returns null to go on, or the `Error` that stops the use case. An after rule
  runs once the change is saved. The rules of an aggregate root without API never run.
- **Factory:** `IXFactory` and the partial class `XFactory` of the application layer; it
  returns a new object, not saved.
- **Event:** `XEvent(string Context, XDto Data)`. The CRUD service publishes `add`, `update`,
  `remove` once the change is saved; publish your own with `IEventPublisher`. Every class of
  the application project implementing `IEventHandler<XEvent>` is registered.

## Extension points

| Where | What |
|---|---|
| `M.Api/Program.cs` | Authentication, `AddMApi()`, `AddMApplication()`, `AddMInfrastructure(options => options.UseSqlite(...))` with the connection string `"M"`, schema creation (`EnsureCreated` or EF migrations), `MapMEndpoints()`. |
| project files | Packages of your own: the database provider in `M.Api`, for instance. |
| `partial class X` (Domain) | `private partial T CalculateP()` for each calculated property `P`; domain methods. |
| `partial interface IXRepository` (Domain) + `partial class XRepository` (Infrastructure) | Queries of your own, on `Db` (the DbContext); override `WithDetails` to load more navigations in `FindAsync`. |
| `partial class MDbContext` (Infrastructure) | `partial void OnModelCreatingPartial(ModelBuilder)`: seeding (`HasData`), indexes. |
| `partial class XService` (Application, CRUD) | `private partial Task<Error?> RuleAsync(X aggregate, CancellationToken)` for each rule. |
| `partial class XService` (Application, model service) | The methods of `IXService`. Properties: the repositories of `dependencies`, `UnitOfWork`, `CurrentUser`, `Services` (any other registered service). |
| `partial class XFactory` (Application) | The methods of `IXFactory`. |
| `partial class XInput` / `XDto` of a transient (Application) | `partial void OnValidating(Dictionary<string, string[]> errors)`: rules of your own. |
| any class of `M.Application` | `IEventHandler<XEvent>`: a handler, registered automatically. |
| an interface in `M.Application`, implemented in `M.Api` or `M.Infrastructure` | What the inner layers need from the outside (a token issuer, a clock, a mail sender), registered in `Program.cs`. |

## Framework contracts

Read the `*.f.cs` files for the details; the contracts are:

- `Result<T>` / `Result`: a value or an `Error`, both implicitly converted
  (`return dto;`, `return Error.NotFound();`). `Error.Kind`: `NotFound` (404), `Invalid`
  (400, with `Errors` by path), `Conflict` (409), `Forbidden` (403).
- `IRepository<T>`: `FindAsync(id)` (tracked, with details), `QueryAsync(PageRequest)`
  (not tracked), `Add`, `Remove`. Nothing is saved until `IUnitOfWork.SaveChangesAsync()`,
  which returns null or a conflict.
- `IUnitOfWork.ExistsAsync<T>(id)`: whether an aggregate root or entity exists.
- `ICurrentUser`: `IsAuthenticated`, `Name`, `HasRight(right)`.
- `IEventPublisher.PublishAsync(event)`: runs the handlers now, one after the other.
- `ApiTestBase`: the API in memory on a SQLite database per test; the client is a test
  user holding every right; `AuthenticateAs(rights)`, `Unauthenticate()`,
  `PostAsync<T>(uri, body)`, `AssertInvalidAsync(response, property)`;
  override `UseTestAuthentication` (false: the authentication of `Program.cs`) and
  `ConfigureWebHost` (replace or add services).

## Testing

Integration tests through the real endpoints, deriving from `ApiTestBase`. Test what was
written by hand: each rule, service method, factory, handler, calculated property and
`OnValidating` rule, each right, plus one round trip per aggregate root to catch a model
change that breaks the API. The generated tests already check that every query answers,
refuses an anonymous caller and returns 404 for an unknown id.
